🎯 Über die App

Foto-Challenge ist eine Web-App für Partys, Hochzeiten und Feiern. Der Gastgeber legt eine Session an und erhält einen druckbaren QR-Code-Poster, das mehrfach in der Halle aufgehängt werden kann. Gäste scannen den Code, geben ihren Namen ein und bekommen aus einem Pool von 65 Foto-Aufgaben eine gestellt — Aufgaben, die die Gemeinschaft stärken und nie peinlich sind. Jedes Foto landet in einer gemeinsamen Galerie, die per Passwort geschützt ist.

Kein App-Download, keine Registrierung. Für Gäste: QR scannen → Name → Aufgabe → Foto. Fotos sind auth-geschützt und best-effort nicht herunterladbar.

✨ Features

Gastgeber-Flow

Event erstellen mit Name, Gästezahl sowie Galerie- und Gast-Passwort. Dashboard mit Übersicht, Galerie und Einladen.

Druckbares QR-Poster

Aufhängbares Poster mit QR-Code, der direkt auf die Beitritts-Seite des Events zeigt.

65 Foto-Aufgaben

Kuratiert und kategorisiert — gemeinschaftsstärkend statt peinlich. Gäste können die Aufgabe rotieren.

Geschützte Galerie

Fotos werden nur mit gültigem Gast- oder Gastgeber-Cookie inline ausgeliefert. Fremde werden geblockt.

PWA

Web-Manifest, Service Worker (App-Shell-Caching), iOS-Homescreen-Icon. Installierbar.

Kein Build-Step

Server-gerenderte SPA-Shell + Vanilla JS. Leichtgewichtiges Deployment.

🔀 Abläufe

Gastgeber

  1. Event erstellen (Name, Gästezahl, Passwörter) und hostToken erhalten.
  2. Dashboard unter /host/:id?t=TOKEN öffnen.
  3. QR-Poster drucken und in der Location aufhängen.
  4. Fotos live in der Galerie mitverfolgen.

Gast

  1. QR-Code scannen → Beitritts-Seite /:id.
  2. Namen eingeben (+ Gast-Passwort).
  3. Foto-Aufgabe erhalten (optional rotieren).
  4. Foto aufnehmen → Erfolg → gemeinsame Galerie ansehen.

🔐 Auth-Modell

  • Gastgeber: Beim Erstellen wird ein zufälliger hostToken erzeugt. Das Dashboard tauscht ihn gegen ein signiertes Host-Cookie (fch_<id>). Der Token wird zusätzlich in localStorage gespeichert.
  • Gast: Beim Beitreten mit Name + Gast-Passwort wird ein signiertes Gast-Cookie (fcg_<id>) gesetzt.
  • Galerie & Bilder erfordern ein gültiges Gast- oder Host-Cookie — Fremde werden geblockt.
  • Fotos werden inline ausgeliefert; Download wird best-effort verhindert (CSS user-select/drag: none, geblocktes Kontextmenü). Kein echter DRM-Schutz.

🚀 Lokales Setup

git clone https://github.com/konradthiemann/Foto-Challenge.git
cd Foto-Challenge
npm install
cp .env.example .env
# SESSION_SECRET setzen: openssl rand -hex 32
npm run dev

Die App läuft auf http://localhost:3000 (oder PORT).

Environment-Variablen

PORT
Port des Servers (Default 3000, Railway setzt ihn automatisch).
DATA_DIR
Verzeichnis für SQLite-DB und Uploads (Default ./data, auf Railway ein Volume wie /data).
SESSION_SECRET
Pflicht in Produktion. Langer Zufallsstring zum Signieren der Cookies.
PUBLIC_BASE_URL
Basis-URL für QR-Codes / Einladungs-Links. Leer = aus Request abgeleitet.

☁️ Deployment (Railway)

  1. Service anlegen und Repo/Verzeichnis verbinden.
  2. Volume mounten und DATA_DIR darauf zeigen lassen (z. B. /data).
  3. Env-Variablen setzen: SESSION_SECRET, DATA_DIR, NODE_ENV=production, PUBLIC_BASE_URL.
  4. Deployen — railway.json regelt Build (NIXPACKS) und Start (npm start).
Wichtig: engines.node ist auf 22.x gepinnt. better-sqlite3 und sharp haben für Node 22 Prebuilt-Binaries — bei neueren Versionen schlägt der Build fehl. Node-Version nicht lockern.
